# 持续交互：Codex 驱动审阅与下一轮

用户要求“持续交互”“循环推进”“做完读取后继续派发”时，使用本流程。Codex 是决策者；ZCode 是执行者。随附脚本只负责执行和证据读取，没有一个会代替 Codex 分析结果或自动判定目标达成。

## 固定目标，逐轮做决定

先把当前已授权目标、工作目录、交付物和完成判据写入 `GOAL.md`。只有缺少真实任务且不能合理推断时才澄清。指定 3 轮只适用于用户要求的演示；实际工作可以持续到目标完成，不应无故套用 3 轮上限。

维护一个小型 `LOOP_STATE.json`，例如：

```json
{
  "loop_id": "unique-loop",
  "objective_file": "/absolute/GOAL.md",
  "status": "running",
  "backend": "desktop_chat",
  "session_id": "sess_actual",
  "current_round": 1,
  "max_rounds": null,
  "rounds": [
    {"round": 1, "marker": "unique-round-1", "task_file": "/absolute/round-1/task.md", "state": "dispatched"}
  ]
}
```

这是恢复入口，不是额外的审批系统。保留每轮任务、执行快照、关键产物版本和 Codex 的 `review.md`，让中断后能接着分析，而不是把同一任务再发一遍。

每轮按以下顺序推进：

1. **派发。** 明确本轮要改变什么、依据哪些真实输入、允许改哪些文件、如何验收。首轮可以是最小实现；后续指令必须来自上一轮实际输出和 Codex 的审阅，不能预写完整的所有轮次再机械播放。
2. **等待新回复。** 消息已发送不等于执行完成。绑定该轮唯一 marker 与真实会话 ID，直到本轮 completed/error/cancelled。运行期间不要往输入框堆积下一轮指令。
3. **读取。** 收集本轮回复、实际模型、工具与产物。源码、数据、文献或渲染产物按任务需要直接检查，不能只看 ZCode 的 RESULT.json 自报。
4. **分析与验收。** Codex 根据目标判据做必要检查，明确已通过什么、还缺什么、具体反例或证据是什么。区分缺陷与有意留到下一阶段的功能。保存 review。
5. **继续或收尾。** 在已有目标和授权范围内写下一轮具体要求并实际发送，不在每轮结束后停下来等用户重复说“继续”。如果目标已完成，或达到用户指定轮数，则交付；有实质权限变化或无法自行解决的阻塞才交回用户。

不要把固定的“继续优化”“再检查一遍”当作分析。不要制造问题凑轮数。相同失败再次出现时应根据证据更换方法；没有新信息和可执行改进时停止空转并报告原因。

## 会话与轮次必须分清

### 可见聊天

在同一个由本流程管理的 ZCode 聊天中发送后续消息。保留 `session_id`，每轮换唯一 marker。不要使用只看“最后状态”的查询来等下一轮：上一轮可能早已 completed，而新消息还在队列中。

```bash
python3 <skill-dir>/scripts/zcode_round.py \
  --session-id sess_actual \
  --marker UNIQUE_LOOP_ROUND_2 \
  --workspace /absolute/project \
  --wait-seconds 45 \
  --output /absolute/round-2/execution.json
```

该工具将 marker → 真实 user message → turn_usage.user_message_id 绑定，排除运行时的 synthetic user 提醒，且只收集对应 parentID 的回复/工具。`not_started`、`pending_turn_record`、`running` 都不能当成完成。实际观察到运行统计可能到回合结束才落盘，因此 `pending_turn_record` 不等于确定仍在排队。`not_started` 也不表示可以立即重发：先检查 UI 或排队状态。多个匹配时必须消除歧义，不能自动取最新。

每次等待最多 60 秒，以便 Codex 继续处理用户输入和更新进度；未结束时再继续等待。会话/数据库 schema 不兼容时读界面或准确诊断，不修改 ZCode 的数据库。输出字段 `ready_for_codex_review` 不等于验收通过。

### CLI / 无图形会话

当前可靠实现为每轮使用新的 `run-dir` 和 `zcode_run.py` 调用，记录各轮 session ID。共同的 GOAL、产品目录、上一轮执行快照和 review 提供连续上下文；下一轮任务包必须显式引用这些材料。此模式支持持续审阅推进，但不宣称这些 CLI 调用共享一个聊天会话。

不要混用 GUI 与 CLI 并发写同一个会话。UI 对话需要可见连续性时走 UI；CLI 每轮独立执行时依靠文件交接。若用户专门要求 CLI 同一会话续跑，需另行验证当前版本 `--resume` 的运行状态与上下文行为，不能仅凭帮助中存在选项宣称支持。

## 时间、暂停和续接

每轮派发前执行当前用户的已授权时段规则。若本机启用了北京时间工作日 14:00-18:00 暂停，则照此执行；明确授权的本次例外应记录范围，不重复询问。免费窗口结束不等于任务必须停止。

进入暂停时段、需要真实输入、认证失败或用户暂停时，先写状态及唯一下一步。用户要求后台、离线或稍后继续，或已要求持续推进且任务实际需要跨越本次活跃回合/暂停时段时，用当前 Codex 的正式自动化/heartbeat 工具落实同一授权范围内的续接；不再为同一工作重复要授权，不编造自己能在回合结束后自行醒来。若当前环境没有这样的工具，如实保存并交付续接入口。已经达成目标或用完约定轮数，则不创建无用的后续任务。

正常状态只在阶段变化、关键发现、完成、失败或需要用户操作时通知；不要反复汇报相同的“仍在运行”。当前活跃对话内的循环保持工作到本次约定终点，不为每轮新建用户任务。
